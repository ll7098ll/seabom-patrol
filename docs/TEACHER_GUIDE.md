# 교사용 수업 안내

[README로 돌아가기](../README.md)

## 목표

학생이 지도 자료의 의미와 한계를 구별하고, 여러 근거로 배치를 제안한 뒤 같은 조건의 실험으로 판단을 수정하도록 돕습니다. 특정한 배치 정답이나 최저 평균값 하나를 찾는 활동으로 제한하지 않습니다.

## 40분 수업 예시

| 시간 | 활동 | 교사 발문 |
|---|---|---|
| 5분 | 도시와 문제 만나기 | ‘10대로 도시 전체를 어떻게 살필까요?’ |
| 10분 | 두 가지 이상의 자료 비교·근거 수집 | ‘요청이 많은 곳과 사람이 모이는 곳이 같은가요?’ |
| 8분 | 10대 배치와 기준 저장 | ‘이 차량을 이 도로에 놓은 근거는 무엇인가요?’ |
| 10분 | 운영 재생·수정·재실험 | ‘기다린 요청은 어디에 있고 담당차는 무엇을 하고 있나요?’ |
| 7분 | 결과 설명·JSON 보관 | ‘무엇이 좋아졌고 어떤 곳은 더 불리해졌나요?’ |

첫 수업 전 npm ci와 빌드를 마쳐 두고 학생용 기기에서 화면을 확인하세요. 학교 환경에서 npm 설치가 어렵다면 미리 정적 호스팅으로 게시한 주소를 사용합니다. 휴대전화에서는 자료·지도·근거 패널을 전환해서 읽습니다.

## 토론 질문

- 전체 요청 수와 확인된 사건 수는 어떻게 다른가요?
- CCTV가 많거나 적다는 사실만으로 안전을 판단할 수 있나요?
- 직선으로 가까운 차량이 다리·일방통행 때문에 늦어질 수 있나요?
- 요청 수가 적어도 어린이·어르신·보행 불편을 고려해야 하는 곳은 어디인가요?
- 평균 도착이 짧아졌는데 미도착이나 일부 구역의 대기가 늘었다면 어떻게 판단할까요?
- 차량이 가용한데도 다른 구역 일반 요청을 보내지 않는 정책은 결과에 어떤 영향을 주나요?

## 관찰과 평가

평가는 ‘자료의 기간·단위를 구분했는가’, ‘두 가지 이상 근거를 연결했는가’, ‘같은 요청·같은 기준으로 비교했는가’, ‘불리해진 구역과 모형 한계를 설명했는가’를 중심으로 합니다. 빠른 조작이나 가장 짧은 평균만으로 평가하지 않습니다.

관찰 자료와 실험 자료의 기간은 다릅니다. 배치·순찰 코스는 과거 관찰 자료를 바탕으로 만들며 미래 실험 주간 요청을 미리 사용하지 않습니다. 주민 발언과 자발적 설문은 대표 표본이 아닙니다.

## 수업 전후 확인

1. 기준 배치 저장의 의미와 ‘거리만 비교’/일주일 운영의 차이를 설명합니다.
2. 동시 요청, 지원 차량과 미도착 항목을 함께 읽도록 안내합니다.
3. 각 모둠이 같은 기준 배치로 비교하는지 확인합니다.
4. 종료 전에 JSON을 내보내고 제출 파일을 열 수 있는지 확인합니다.
5. 공용 기기에서는 다음 모둠을 위해 브라우저의 해당 사이트 저장 자료를 정리합니다.

이 활동은 가상 도시를 다루는 탐구 수업입니다. 실제 경찰 인력·배치 결정을 뒷받침하는 성능 평가 자료로 사용하지 않습니다.
