# 패키지 검증 기록

[README로 돌아가기](../README.md)

확인일: **2026-10-29 (한국 시간)**. Windows, Node.js **24.14.0**, Microsoft Edge headless에서 확인했습니다. 아래는 이 업로드용 사본에서 실제 실행한 결과입니다.

## 설치·계산·빌드

| 확인 | 결과 |
|---|---|
| npm ci --no-audit --no-fund | 성공, lockfile 기준 66개 패키지 설치 |
| npm run verify | 40개 통과: 기존 전역 배정 회귀 26개, 전담 순찰 14개 |
| npm run check:package | 이전 사이트 14개 SHA-256, 필수 자료, 문서 로컬 링크, 로컬 설정 제외, 자산 기본 경로 확인 |
| npm run build | 성공, Vite 7.3.7 프로덕션 빌드 |
| /saebom-check/ 기본 경로 빌드 | 성공, JSON·브랜드·글꼴·Worker·이전 사이트 경로 확인 |

모형 검사는 도로 중간 배치, 일방통행, 요청·업무 시간 보존, 동시 요청과 중복 업무 방지, 담당차 대기, 인접 지원, 구역·격자 소속, 순찰 중 실제 위치에서 출동, 코스 재합류, 미래 요청과 코스 생성의 분리 등을 포함합니다.

상세 모형 결과는 [verification.json](../public/data/verification.json)에 있습니다. 기존 전역 배정 회귀 검사의 정책과 현재 전담 순찰 정책은 다릅니다. 검사 통과는 실제 경찰 성능을 검증했다는 뜻이 아닙니다.

## 브라우저 확인

개발 서버 루트 주소와 /saebom-check/ 하위 경로의 프로덕션 미리보기에서 다음 흐름을 확인했습니다.

1. 도시 자료를 불러오고 장소 근거를 1개 담았습니다.
2. 관찰을 마치고 분산 예시 10대를 배치·기준 저장했습니다.
3. Worker로 일주일 운영을 계산하고 운영 재생 차량 10개를 확인했습니다.
4. 계산 원리·검증 창과 검증 JSON을 열었습니다.
5. 배치 JSON을 내려받아 차량 10대와 근거 1개를 확인하고 다시 불러왔습니다.
6. 이전 사이트와 도시 JSON·로고·글꼴이 HTTP 200으로 열리는지 확인했습니다.
7. 1440×1050 데스크톱과 390×844 모바일 화면을 열고 모바일 가로 넘침이 없는지 확인했습니다.

해당 브라우저 흐름에서 JavaScript 오류와 HTTP 400 이상 응답은 없었습니다. 마지막 프로덕션 하위 경로 확인 원문은 [browser-verification.json](browser-verification.json)에 있습니다. 테스트 주소는 로컬 임시 주소이며 공개 배포 주소가 아닙니다.

[README 화면 이미지](images/observation.png)는 이 사본의 실제 도시 관찰 화면을 캡처한 것입니다.

## 포장과 범위

최종 폴더와 ZIP에는 node_modules/, dist/, .git/, .openai/, .sites-runtime/를 포함하지 않습니다. [파일 해시 목록](PACKAGE_MANIFEST.json)은 최종 소스 파일을 SHA-256으로 기록하며, 목록 파일 자체는 제외합니다. ZIP을 만든 뒤 내부 파일 목록과 각 해시를 원본 폴더와 대조합니다.

기준 saebom-site-update 작업 폴더의 Git 변경 사항은 없음을 확인했습니다. GitHub Actions의 원격 실행과 실제 GitHub Pages 게시는 실행하지 않았습니다. 모든 브라우저·운영체제·보조공학 조합을 검사한 것은 아니며 데이터 생성 과정의 전체 재생성도 검증 범위에 포함하지 않습니다.
